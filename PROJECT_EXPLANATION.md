# StudyFlow - Student Technical Guide & Viva Preparation

This document explains the technical architecture, inner workings, and source code of **StudyFlow** in beginner-friendly language. It is designed to help you confidently explain and defend your project during a college viva examination.

## 1. High-Level Architecture Overview

StudyFlow follows a standard **Three-Tier Architecture**:

```
+-------------------------------------------------------+
|                    PRESENTATION LAYER                 |
|   Vaadin Flow Java Components (Pure Java, No HTML/JS) |
|   - MainLayout, DashboardView, TasksView              |
|   - TaskFormDialog, ConfirmDeleteDialog               |
+-------------------------------------------------------+
                           |
                           v
+-------------------------------------------------------+
|                     BUSINESS LAYER                    |
|   Spring Service Beans                                |
|   - TaskService: Calculations, Validation, Filtering  |
+-------------------------------------------------------+
                           |
                           v
+-------------------------------------------------------+
|                   DATA ACCESS LAYER                   |
|   Spring Repository Beans                             |
|   - TaskRepository: Parameterized SQL & JdbcTemplate   |
+-------------------------------------------------------+
                           |
                           v
+-------------------------------------------------------+
|                    DATABASE LAYER                     |
|   H2 Database (Local Persistent File Storage)         |
|   - ./data/studyflowdb.mv.db                          |
+-------------------------------------------------------+
```

## 2. Explanation of Every Class

### 1. `StudyFlowApplication.java`
- **Location**: `com.studyflow`
- **Purpose**: The main starting point of the Spring Boot application.
- **Key Concepts**:
  - Contains `public static void main(String[] args)`, which boots up Spring Boot's embedded Tomcat web server.
  - Implements `AppShellConfigurator` and has `@Theme(value = "studyflow", variant = Lumo.DARK)` to apply Vaadin's modern dark theme across all views.

### 2. `Priority.java`
- **Location**: `com.studyflow.model`
- **Purpose**: An `enum` (Enumeration) defining the three possible urgency levels of an assignment: `LOW`, `MEDIUM`, and `HIGH`.
- **Why use an Enum?**: Enums prevent invalid inputs (like a misspelled priority) and restrict values to a safe, predefined set.
- **Helper methods**: Contains `getDisplayName()` and `getColorCode()` for UI badge coloring.

### 3. `TaskStatus.java`
- **Location**: `com.studyflow.model`
- **Purpose**: An `enum` representing the task state: `PENDING` or `COMPLETED`.
- **Viva Benefit**: Clear and extensible if future statuses (like `IN_PROGRESS`) are needed.

### 4. `Task.java`
- **Location**: `com.studyflow.model`
- **Purpose**: The primary entity model (POJO - Plain Old Java Object).
- **Fields**:
  - `Long id`: Unique primary key generated by the database.
  - `String title`: Name of the assignment.
  - `String subject`: Academic course (e.g., DAA, DBMS, Java).
  - `String description`: Optional task details or notes.
  - `LocalDate dueDate`: Deadline date from `java.time.LocalDate`.
  - `Priority priority`: Urgent level.
  - `TaskStatus status`: Progress state.
  - `LocalDateTime createdAt`: Timestamp of when the task was created.
- **Helper methods**:
  - `isOverdue()`: Checks if the task is pending and the due date is strictly before `LocalDate.now()`.
  - `isDueToday()`: Checks if the task is pending and due today.
  - `isDueSoon()`: Checks if the task is pending and due within the next 3 days.

### 5. `TaskRepository.java`
- **Location**: `com.studyflow.repository`
- **Purpose**: Directly talks to the H2 database using Spring's `JdbcTemplate`.
- **Key Methods**:
  - `initTable()`: Runs `CREATE TABLE IF NOT EXISTS tasks (...)` on startup to ensure database readiness.
  - `save(Task task)`: Executes parameterized `INSERT` if `task.getId() == null`, or parameterized `UPDATE` if `id` exists. Uses `GeneratedKeyHolder` to retrieve the database-assigned ID.
  - `findAll()`: Executes `SELECT * FROM tasks ORDER BY due_date ASC, id DESC`.
  - `findById(Long id)`: Fetches a single task by ID.
  - `deleteById(Long id)`: Executes `DELETE FROM tasks WHERE id = ?`.
  - `count()`: Runs `SELECT COUNT(*) FROM tasks`.

### 6. `TaskService.java`
- **Location**: `com.studyflow.service`
- **Purpose**: The business logic engine of the application.
- **Key Methods**:
  - `saveTask(Task task)`: Validates that title, subject, and due date are provided before saving.
  - `toggleStatus(Long id)`: Inverts a task's status (`PENDING` <-> `COMPLETED`) with one call.
  - `getCompletionPercentage()`: Calculates `(completed / total) * 100`, returning `0` if `total == 0` to avoid division-by-zero errors.
  - `getOverdueCount()`: Uses a simple for-each loop to count pending tasks whose deadlines have passed.
  - `searchAndFilter(query, status, priority)`: Filters tasks in memory by matching keywords and matching enum statuses.
  - `initSampleData()`: Seeds realistic college assignments on first boot if the database is empty.

### 7. `MainLayout.java`
- **Location**: `com.studyflow.view`
- **Purpose**: The master frame containing the responsive side drawer (navigation links to Dashboard, My Tasks, and Completed) and top header bar (live system date and global "+ New Task" button).

### 8. `DashboardView.java`
- **Location**: `com.studyflow.view`
- **Purpose**: The home screen (`/`).
- **Features**:
  - Four stat cards: Total Tasks, Pending, Completed, Overdue.
  - Progress bar showing completion percentage.
  - Upcoming deadlines grid with urgency tags ("OVERDUE", "TODAY", "SOON").
  - "Reset Sample Data" button for testing and demonstration.

### 9. `TasksView.java`
- **Location**: `com.studyflow.view`
- **Purpose**: The main task management screen (`/tasks`).
- **Features**:
  - Real-time search field with 250ms debounce.
  - Dropdown filters for Status and Priority.
  - Interactive table with single-click completion toggles, edit buttons, and delete buttons.
  - Friendly empty states when no records match.

### 10. `CompletedTasksView.java`
- **Location**: `com.studyflow.view`
- **Purpose**: Dedicated archive view (`/completed`) showing completed coursework with strike-through styling, restore capability, and permanent deletion.

### 11. `TaskFormDialog.java` & `ConfirmDeleteDialog.java`
- **Location**: `com.studyflow.components`
- **Purpose**: Modal popups that handle user input validation for task creation/editing and prevent accidental deletion.

## 3. How Java Connects to H2 Database

1. **Driver & Connection**:
   - The dependency `com.h2database:h2` provides the JDBC driver (`org.h2.Driver`).
   - In `application.properties`, we configure:
     ```properties
     spring.datasource.url=jdbc:h2:file:./data/studyflowdb;DB_CLOSE_DELAY=-1
     spring.datasource.driverClassName=org.h2.Driver
     spring.datasource.username=sa
     spring.datasource.password=
     ```
2. **Persistence**:
   - Because `jdbc:h2:file:./data/studyflowdb` specifies a file path (not `jdbc:h2:mem:`), H2 writes table data to `studyflowdb.mv.db` in the `data/` folder.
   - When the server stops or restarts, the file remains intact, ensuring persistent storage.
3. **Execution via `JdbcTemplate`**:
   - Spring Boot injects `JdbcTemplate` into `TaskRepository`.
   - `JdbcTemplate` handles opening connections, creating statements, executing queries, catching SQLExceptions, and closing connections automatically.

## 4. How Vaadin Flow Creates the UI in Pure Java

Vaadin Flow allows developers to write the entire user interface using Java objects:
- Every HTML component is represented by a Java class:
  - `<button>` -> `new Button("Save")`
  - `<input type="text">` -> `new TextField("Task Title")`
  - `<div>` / `layout` -> `new VerticalLayout()`, `new HorizontalLayout()`
  - `<table>` -> `new Grid<Task>(Task.class)`
  - `<dialog>` -> `new Dialog()`
- **Event Handling**:
  - We attach click listeners using Java lambdas:
    ```java
    Button btn = new Button("Submit", event -> handleSave());
    ```
- **How it reaches the browser**:
  - The Java components run on the server. Vaadin's engine synchronizes the component state with Web Components running in the browser via automated WebSocket / HTTP communication.

## 5. How CRUD Operations Work in Code

### CREATE (Insert)
```java
// In TaskRepository.java
String insertSql = "INSERT INTO tasks (title, subject, description, due_date, priority, status, created_at) VALUES (?, ?, ?, ?, ?, ?, ?)";
KeyHolder keyHolder = new GeneratedKeyHolder();

jdbcTemplate.update(connection -> {
    PreparedStatement ps = connection.prepareStatement(insertSql, new String[]{"ID"});
    ps.setString(1, task.getTitle());
    ps.setString(2, task.getSubject());
    ps.setString(3, task.getDescription());
    ps.setDate(4, Date.valueOf(task.getDueDate()));
    ps.setString(5, task.getPriority().name());
    ps.setString(6, task.getStatus().name());
    ps.setTimestamp(7, Timestamp.valueOf(task.getCreatedAt()));
    return ps;
}, keyHolder);

// Extract generated ID
Number generatedId = (Number) keyHolder.getKeys().get("ID");
task.setId(generatedId.longValue());
```

### READ (Select All)
```java
// In TaskRepository.java
String sql = "SELECT * FROM tasks ORDER BY due_date ASC, id DESC";
return jdbcTemplate.query(sql, taskRowMapper);
```

### UPDATE (Modify)
```java
// In TaskRepository.java
String updateSql = "UPDATE tasks SET title = ?, subject = ?, description = ?, due_date = ?, priority = ?, status = ? WHERE id = ?";
jdbcTemplate.update(
    updateSql,
    task.getTitle(),
    task.getSubject(),
    task.getDescription(),
    Date.valueOf(task.getDueDate()),
    task.getPriority().name(),
    task.getStatus().name(),
    task.getId()
);
```

### DELETE (Remove)
```java
// In TaskRepository.java
String sql = "DELETE FROM tasks WHERE id = ?";
jdbcTemplate.update(sql, id);
```

## 6. How Task Statistics are Calculated

In `TaskService.java`, statistics use simple, readable loops:

### 1. Completion Percentage
```java
public int getCompletionPercentage() {
    List<Task> tasks = taskRepository.findAll();
    int total = tasks.size();
    
    // Safety check: Prevent division-by-zero
    if (total == 0) {
        return 0;
    }

    int completed = 0;
    for (Task task : tasks) {
        if (task.getStatus() == TaskStatus.COMPLETED) {
            completed++;
        }
    }

    double percentage = ((double) completed / (double) total) * 100.0;
    return (int) Math.round(percentage);
}
```

### 2. Overdue Count
```java
public int getOverdueCount() {
    List<Task> tasks = taskRepository.findAll();
    int overdue = 0;
    for (Task task : tasks) {
        if (task.isOverdue()) {
            overdue++;
        }
    }
    return overdue;
}
```

## 7. How Search & Filtering Works

In `TaskService.searchAndFilter(query, statusFilter, priorityFilter)`:
1. We retrieve all tasks from the database.
2. We iterate through each task and apply three checks:
   - **Search check**: Does the lowercase query appear in the task title or subject? (`title.contains(query) || subject.contains(query)`)
   - **Status check**: Does the task match `"PENDING"`, `"COMPLETED"`, or is the filter `"ALL"`?
   - **Priority check**: Does the task match `"HIGH"`, `"MEDIUM"`, `"LOW"`, or is the filter `"ALL"`?
3. Only tasks that satisfy all three conditions are added to the returned list.

## 9. 20 Possible Viva Questions & Answers

### Q1: What is StudyFlow?
**Answer**: StudyFlow is a student study planner web application written in Java with Spring Boot, Vaadin Flow, and H2 database that helps college students organize academic assignments, track deadlines, and monitor completion progress.

### Q2: What architecture does StudyFlow follow?
**Answer**: It follows a 3-tier architecture: the Presentation layer (Vaadin Java UI), the Business layer (Spring Service), and the Data Access layer (Spring JDBC Repository connecting to an H2 database).

### Q3: Why did you use Vaadin Flow instead of HTML/JavaScript?
**Answer**: Vaadin Flow allows writing complete modern web user interfaces purely in Java with type safety, compile-time checking, and automated state synchronization without needing separate JavaScript frontends like React or Angular.

### Q4: Why did you use H2 database instead of MySQL or PostgreSQL?
**Answer**: H2 is a lightweight, zero-configuration relational SQL database that can run embedded as a local file. It requires no separate server installation, making the project completely self-contained and portable for college demonstrations.

### Q5: How do you ensure tasks are not lost when the application restarts?
**Answer**: By configuring the JDBC URL as `jdbc:h2:file:./data/studyflowdb`, H2 writes and commits all table data directly to a local disk file (`studyflowdb.mv.db`), guaranteeing persistence across restarts.

### Q6: What is the difference between `Statement` and `PreparedStatement` in JDBC?
**Answer**: `PreparedStatement` pre-compiles SQL queries and uses parameterized placeholders (`?`). This prevents SQL Injection attacks and improves execution performance compared to regular `Statement`.

### Q7: How does your application prevent SQL Injection?
**Answer**: All user inputs in `TaskRepository` are passed as parameters to Spring's `JdbcTemplate.update(...)` and `query(...)` using `?` placeholders, ensuring user data is treated strictly as literals, never executable SQL.

### Q8: What does the `@Repository` annotation do?
**Answer**: `@Repository` is a Spring stereotype annotation that marks a class as a Data Access Object (DAO) and enables automatic Spring component scanning and database exception translation.

### Q9: What does the `@Service` annotation do?
**Answer**: `@Service` marks a class as a business service bean in Spring's application context, separating business logic (like calculations and validations) from data access.

### Q10: How does StudyFlow prevent division-by-zero errors in completion progress?
**Answer**: In `TaskService.getCompletionPercentage()`, we check `if (total == 0) return 0;` before performing any division.

### Q11: How do you determine if an assignment is "Overdue"?
**Answer**: In `Task.isOverdue()`, we check: `status == TaskStatus.PENDING && dueDate.isBefore(LocalDate.now())`. If it is already completed, it cannot be overdue.

### Q12: Why did you use `java.time.LocalDate` instead of the legacy `java.util.Date`?
**Answer**: `LocalDate` (introduced in Java 8) is immutable, thread-safe, and provides clear, intuitive comparison methods like `isBefore()`, `isAfter()`, and `isEqual()`.

### Q13: What is the purpose of the `RowMapper` in `TaskRepository`?
**Answer**: Spring's `RowMapper<Task>` maps each row of the SQL `ResultSet` to our Java `Task` object, converting column values like `due_date` and `priority` to their corresponding Java types.

### Q14: How does sample data seeding work without duplicating tasks on restart?
**Answer**: On startup, `TaskService.initSampleData()` checks `if (taskRepository.count() == 0)`. If records already exist in H2, seeding is skipped.

### Q15: How does the Create Task form validate input?
**Answer**: In `TaskFormDialog`, before calling the service, we verify that `title` and `subject` are non-empty and a valid `dueDate` is selected. If invalid, `setInvalid(true)` displays an inline error message and halts submission.

### Q16: How does the status toggle work?
**Answer**: When the user clicks the completion icon on a task row, `taskService.toggleStatus(id)` loads the task, flips `PENDING` to `COMPLETED` (or vice-versa), saves it to H2, and refreshes the UI and dashboard metrics immediately.

### Q17: How does search work with both title and subject?
**Answer**: `TaskService.searchAndFilter` converts both the query and task attributes to lowercase and checks `title.contains(query) || subject.contains(query)` for case-insensitive matching.

### Q18: What is an Enum in Java, and where is it used here?
**Answer**: An enum is a special Java data type that defines a fixed set of constants. StudyFlow uses `Priority` (`LOW`, `MEDIUM`, `HIGH`) and `TaskStatus` (`PENDING`, `COMPLETED`).

### Q19: How do you run the H2 database web console?
**Answer**: With `spring.h2.console.enabled=true` in `application.properties`, we can open `http://localhost:8080/h2-console` in any browser and query the tables directly.

### Q20: What happens when a user attempts to delete a task?
**Answer**: A modal `ConfirmDeleteDialog` appears asking the student to confirm. The record is only deleted if the user clicks the red "Delete Task" button, preventing accidental data loss.

### Q21: How does StudyFlow use the Browser's LocalStorage as a database?
**Answer**: When a student opens StudyFlow, `MainLayout.onAttach()` executes client-side JavaScript to retrieve `studyflow_tasks` from `window.localStorage`. If saved tasks exist, `TaskService.loadSessionTasksFromJson()` deserializes the JSON string into the user's active session. Whenever a task is created, modified, toggled, or deleted, `TaskService.syncToLocalStorage()` immediately serializes the updated list to JSON and writes it back to `window.localStorage.setItem('studyflow_tasks', json)`. This ensures each visitor gets their own private, persistent database directly on their device.

### Q22: Why is the LocalStorage database ideal when hosting on Render or free cloud platforms?
**Answer**: Free hosting platforms like Render utilize ephemeral containers that spin down after 15 minutes of inactivity and reset their local filesystem on restart. By storing student data in the Browser's LocalStorage:
1. Student assignments are never wiped when the Render container goes to sleep or restarts.
2. Multiple users (e.g. evaluating professors and students) visiting the same Render link do not overwrite or delete each other's tasks.
3. The application binds dynamically to Render's `$PORT` environment variable (`server.port=${PORT:8080}`) and includes memory-tuned JVM flags (`-XX:+UseContainerSupport -XX:MaxRAMPercentage=75.0 -Xmx384m`) to fit safely within Render's 512MB RAM free tier limit.

### Q23: What is the purpose of the `/api/health` endpoint and how does it work with cron-job.org?
**Answer**: Free-tier cloud instances on Render sleep after 15 minutes without requests. `HealthController` provides a dedicated Spring `@RestController` endpoint at `/api/health`, `/health`, and `/ping` returning HTTP 200 OK with system status in < 2ms. By configuring a free scheduler like `cron-job.org` to send a GET request every 10–14 minutes, the Render instance stays warm and active 24/7 without cold-start latency, without creating heavy Vaadin UI sessions.
